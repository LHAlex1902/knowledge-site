1 第 1 章 🧭 框架总览：它到底做了什么

ok-script 是一个基于图像识别的游戏自动化框架。它的全部工作，本质就是一个不断重复的循环——截一张图 → 在图里找目标 → 决定点哪 → 模拟点击 → 等界面变化 → 再截一张图。看懂这个循环，就看懂了整个框架。

1.1 🎯 框架解决的核心难题

2 第 2 章 🏗️ 架构分层：代码是怎么组织的

ok-script 的 ok/ 包按职责分成清晰的几层。越靠下越是「操作系统的脏活」，越靠上越是「用户写的业务」。这种分层让业务代码可以很干净。

层目录职责（楷体注释）
任务层ok/task/用户写业务的地方：BaseTask 基类、任务执行器 TaskExecutor
特征层ok/feature/图像识别核心：Feature 模板、Box 坐标框、FeatureSet 匹配算法
设备层ok/device/截图与输入的具体实现，分 Windows / ADB 两大类
核心层ok/core/事件系统、任务管理、截图通信、翻译等通用能力
UI 层ok/ui/Qt 桌面界面 / Web 界面（可选，与核心解耦）
工具层ok/util/配置、日志、颜色、窗口操作等零碎工具
💡 依赖方向（重要）： 上层依赖下层，下层不知道上层存在。任务层调用特征层做识别，特征层调用设备层做截图——但设备层绝不会反过来调用任务层。这样换掉 UI（比如从 Qt 换成 Web）完全不影响核心逻辑。

3 第 3 章 🖼️ Feature：一张「模板图」在代码里长什么样

我们从最简单的类开始。Feature 代表一张从游戏里截下来的小图（模板），比如一个「确认按钮」的截图。它是整个识别系统的最小数据单元。

Pythonok/feature/Feature.py（完整源码 + 逐行注释）
import numpy as np   # 导入 numpy：所有图像在 Python 里都是 ndarray 数组

class Feature:
    # __init__：创建一个 Feature 要给它一张图，以及这张图在屏幕上的位置
    def __init__(self, mat: np.ndarray, x: int = 0, y: int = 0, scaling=1) -> None:
        self.mat = mat          # mat 是 OpenCV 读进来的图像数组（BGR 三通道）
        self.scaling = scaling  # 缩放系数：不同分辨率下模板要按比例缩放
        self.x = round(x)      # 模板左上角的 x 坐标（四舍五入成整数像素）
        self.y = round(y)      # 模板左上角的 y 坐标
        self.mask = None      # 掩码：匹配时忽略某些像素（如透明区），初始为空
        self.template_cache = {} # 缓存：存灰度化/Canny 后的模板，避免重复处理

    @property           # @property：让 width 像属性一样访问，实际是算出来的
    def width(self):
        return self.mat.shape[1]  # shape[1] 是图像的「宽」（列数）

    @property
    def height(self):
        return self.mat.shape[0]  # shape[0] 是图像的「高」（行数）

    def __str__(self) -> str:
        return str(f'self.x: {self.x}, self.y: {self.y}, width: {self.width}, height: {self.height}')
💡 关键认知： 一张图 = 一个 numpy 数组 + 一个左上角坐标。就这么简单。后面所有的「找图」，本质都是「在大图数组里找一小块和它最像的区域」。mask 和 template_cache 是为匹配精度与性能做的优化。
⚠️【易错点】shape 的行列： OpenCV 图像的 shape 是 (高, 宽, 通道)，即 (行, 列, 通道)。所以 height 取 shape[0]（行），width 取 shape[1]（列）——新手极易写反。

4 第 4 章 📐 Box：识别结果的「坐标+置信度」载体

Box 代表屏幕上的一块矩形区域。它有两个用途：① 当「搜索范围」——只在某块区域里找图，提速；② 当「匹配结果」——找到目标后，用 Box 把坐标和置信度返回给业务。

Pythonok/feature/Box.py（核心方法 + 注释）
class Box:
    # 构造一个矩形框：左上角(x,y) + 宽高 + 匹配置信度 + 名字
    def __init__(self, x, y, width, height, confidence=1.0, name=None):
        self.x = x              # 左上角 x 坐标（像素）
        self.y = y              # 左上角 y 坐标
        self.width = width      # 宽度
        self.height = height    # 高度
        self.confidence = confidence  # 置信度：0~1，越高表示匹配越像
        self.name = name        # 名字：如 "confirm_btn"，方便业务识别

    @property
    def center(self):
        return (self.x + self.width // 2, self.y + self.height // 2)  # 框的中心点，点击通常点这里

    def relative_with_variance(self, rx=0.5, ry=0.5):
        # 按框内相对比例算实际坐标：rx=0.5 表示水平正中，ry=0.5 表示垂直正中
        return (self.x + int(self.width * rx), self.y + int(self.height * ry))

    def crop_frame(self, frame):
        # 用这个框去裁剪大图，取出框内那一小块图像
        return frame[self.y:self.y+self.height, self.x:self.x+self.width]
💡 为什么需要 relative_with_variance？ 有些按钮不能点正中心（比如带勾选框的选项，要点左侧的框）。rx/ry 让你指定「点框内哪个相对位置」，0.5 是正中，0.0 是左/上边缘。
✎ Feature vs Box 的关系： Feature 是「要找的模板图」，Box 是「找到后在哪、有多像」。一次匹配 = 拿 Feature 去匹配，产出一堆 Box。这两个类是整个识别层的「数据骨架」。

5 第 5 章 📸 后台截图：BitBlt 是怎么抓到最小化窗口的画面的

这是 ok-script 区别于普通脚本的第一个核心技术。普通截图（如 pyautogui）截的是「整个屏幕」，窗口最小化就抓不到。而 BitBlt 通过 Windows GDI，直接向窗口的绘图设备上下文（DC）请求画面，所以窗口即使被遮挡也能抓到。

💡 先理解三个 GDI 概念（看懂代码的前提）：
  • DC（设备上下文）：Windows 里「一块可绘制的画布」的句柄，窗口、屏幕各有一个
  • BitBlt：Block Bit Transfer，把一块 DC 的像素「位拷贝」到另一块 DC
  • Bitmap：内存里的一块像素缓冲区，用来接住拷出来的画面
Pythonok/device/capture_methods/bitblt.py（BitBltCaptureMethod 精简 + 逐行注释）
import threading
from ok.device.capture_methods.base import BaseWindowsCaptureMethod
from ok.device.capture_methods.bitblt_utils import capture_by_bitblt, composite_hwnds

class BitBltCaptureMethod(BaseWindowsCaptureMethod):
    name = "BitBlt"   # 方法名，UI 里显示用
    short_description = "fastest, least compatible"  # 最快，但兼容性最差

    def __init__(self, hwnd_window):
        super().__init__(hwnd_window)  # 把「目标窗口」对象存起来（含句柄、尺寸）
        self.dc_object = None      # 屏幕 DC：源，代表整个屏幕
        self.bitmap = None       # 位图：承接拷贝出来的像素
        self.window_dc = None    # 窗口 DC：目标，代表游戏窗口
        self.compatible_dc = None # 兼容 DC：内存画布，BitBlt 需要它中转
        self.lock = threading.Lock()  # 线程锁：截图线程和主线程不能同时操作 GDI 对象

    def do_get_frame(self):
        # with self.lock：加锁，防止多线程同时截图导致 GDI 崩溃
        with self.lock:
            # 1. 算出要截的起点(x,y)和尺寸(width,height)
            x, y = get_crop_point(self.hwnd_window.window_width, self.hwnd_window.window_height,
                                  self.hwnd_window.width, self.hwnd_window.height)
            width = self.hwnd_window.real_width or self.hwnd_window.width
            height = self.hwnd_window.real_height or self.hwnd_window.height
            # 2. 核心一步：调用 win32 的 BitBlt，把窗口那块像素拷进 bitmap
            bg = capture_by_bitblt(self, self.hwnd_window.hwnd, width, height, x, y, render_full)
            # 3. 合成子窗口：游戏窗口可能由多个 hwnd 叠加（如悬浮 UI 层）
            bg = composite_hwnds(bg, self.hwnd_window, self.contexts, render_full)
            return bg   # 返回 numpy 数组（就是「一帧画面」）

    def close(self):
        # 释放所有 GDI 对象：不释放会和截图线程抢资源，导致原生层崩溃(access violation)
        with self.lock:
            clean_up_bitblt(self)
            self.contexts.clear()
✎ 为什么这是「后台」？ 注意整个过程没有调用 pyautogui、没有移动真实鼠标、也不需要窗口在前台——它只是向窗口的 DC 请求像素。所以游戏窗口可以被别的窗口盖住，甚至最小化（取决于渲染方式），照样能截图。
⚠️【BitBlt 的局限】 源码注释明确写了：OpenGL、硬件加速、独占全屏（Exclusive Fullscreen）的窗口，BitBlt 抓不到或抓到黑屏。因为这类窗口绕过了 GDI 直接写显存。遇到这种情况要换 DXGI 桌面复制（desktop_duplication.py）或前台截图。

5.1 🎨 截图基类：统一的「取一帧」接口

Pythonok/device/capture_methods/base.py（BaseCaptureMethod.get_frame）
def get_frame(self):
    # 若收到退出信号，立即返回（让截图线程能优雅停止）
    if self.exit_event.is_set():
        return
    try:
        frame = self.do_get_frame()   # 调子类真正实现（BitBlt/ADB/...）
        if frame is not None:
            # 太小的图判为无效（宽高都≤10 说明没截到）
            if frame.shape[0] <= 10 or frame.shape[1] <= 10:
                return None
            self._size = (frame.shape[1], frame.shape[0])  # 记录尺寸
            # 若是 4 通道(BGRA)，砍掉 Alpha 只留 3 通道(BGR)
            if frame.shape[2] == 4:
                frame = frame[:, :, :3]
        return frame
    except Exception as e:
        raise CaptureException(str(e)) from e  # 统一包装成 CaptureException
💡 模板方法模式： 基类 get_frame 定好「骨架流程」（检查退出→取帧→校验→去Alpha→返回），具体「取帧」交给子类 do_get_frame。这就是面向接口编程，业务只认 get_frame。

6 第 6 章 🖱️ 后台输入：PostMessage 怎么在后台点击

ok-script 的第二个核心技术。后台运行时，真实鼠标在用户手里（用户在用电脑干别的），不能真去动。解法是：绕过鼠标，直接向窗口句柄「投递」一条鼠标/键盘消息，游戏以为是它自己收到的点击。

💡 Windows 消息机制（先理解）： Windows 里所有操作都是「消息」。鼠标点击 = 系统给窗口发 WM_LBUTTONDOWN（左键按下）+ WM_LBUTTONUP（左键抬起）两条消息。PostMessage 就是「我直接往你窗口的消息队列塞一条消息」，游戏无从分辨这是真鼠标还是程序伪造的。
Pythonok/device/interaction_methods/post_message.py（PostMessageInteraction.click 精简 + 注释）
import win32gui, win32con, win32api   # pywin32：Python 调用 Win32 API 的库
from ok.device.interaction_methods.base import BaseInteraction

class PostMessageInteraction(BaseInteraction):
    def click(self, x=-1, y=-1, move_back=False, name=None, down_time=0.01, move=True, key="left"):
        super().click(x, y, name=name)   # 父类钩子：记录日志、画调试框
        # 1. 把游戏内坐标(x,y) 转成「窗口客户区坐标」，再打包成 lParam（一个32位整数）
        if move:
            long_position = self.move(x, y)   # 先发一条鼠标移动消息，更新窗口内部鼠标位置
            time.sleep(down_time)
        else:
            long_position = self.update_mouse_pos(x, y, activate=True)
        # 2. 根据 key 选「按下/抬起」对应的消息常量
        if key == "left":
            btn_down, btn_up = win32con.WM_LBUTTONDOWN, win32con.WM_LBUTTONUP
        else:
            btn_down, btn_up = win32con.WM_RBUTTONDOWN, win32con.WM_RBUTTONUP
        # 3. 核心：投递「按下」消息，wParam 带上鼠标键状态位
        self.post(btn_down, win32con.MK_LBUTTON, long_position)
        time.sleep(down_time)   # 保持按下这么长时间，太短游戏可能不认
        # 4. 投递「抬起」消息，一次点击完成
        self.post(btn_up, 0, long_position)

    def post(self, message, wParam=0, lParam=0, hwnd=None):
        # 真正干活的底层方法：调用 Win32 的 PostMessage 往消息队列塞消息
        if hwnd is None:
            hwnd = self.hwnd
        try:
            win32gui.PostMessage(hwnd, message, wParam, lParam)  # ★ 就是这一句，后台点击的灵魂
        except Exception as e:
            logger.error(f'PostMessage error {hwnd}: {e}')
✎ 坐标转换是难点（update_mouse_pos 干了什么）： 游戏给你的坐标是「截图内坐标」，但 PostMessage 需要「窗口客户区坐标」。所以要先 ClientToScreen 转屏幕坐标，再 ScreenToClient 转回目标窗口坐标，还要判断鼠标落在哪个子窗口句柄上——这套转换保证点击精确命中。
⚠️【后台输入的局限】 有些游戏会校验消息来源（检测 PostMessage 的特征），或用 DirectX 直接读鼠标硬件状态，这类游戏后台点击无效，只能退回「前台真实键鼠」（pydirect/pyautogui）。ok-script 提供了多种 interaction_methods 应对，配置里可切换。

6.1 ⌨️ 键盘输入同理

PythonPostMessageInteraction.send_key（发一个按键）
def send_key(self, key, down_time=0.01):
    super().send_key(key, down_time)  # 记日志（限流，避免刷屏）
    self.send_key_down(key)       # 发 WM_KEYDOWN：把键名转成虚拟键码 VK，打包 lParam
    time.sleep(down_time)          # 按住一会儿
    self.send_key_up(key)         # 发 WM_KEYUP：松开

# make_lparam 把「扫描码 + 按下/抬起标志」打包成 32 位整数，这是 Windows 键盘消息的格式要求
def make_lparam(self, vk_code, is_up=False):
    scan_code = win32api.MapVirtualKey(vk_code, 0)  # 虚拟键码 → 扫描码
    lparam = (scan_code << 16) | 1
    if is_up:
        lparam |= (1 << 30) | (1 << 31)  # 抬起时置高两位
    return lparam

7 第 7 章 🎯 模板匹配：在大图里找出「最像」的那一块

这是识别层的算法核心。有了截图（大图）和 Feature（模板小图），怎么在大图里找到模板所在的位置？答案是 OpenCV 的 matchTemplate——让模板在大图上「滑动」，每滑到一个位置就算一个相似度分数，分数最高的地方就是匹配点。

Pythonok/feature/FeatureSet.py · find_one_feature（核心匹配逻辑精简 + 注释）
def find_one_feature(self, mat, category_name, ..., threshold=0, box=None, ...):
    if mat is None:
        return []                    # 截图失败，返回空
    if threshold == 0:
        threshold = self.default_threshold  # 没传阈值就用默认(0.95)
    # 1. 取出模板图（若没直接给，就按名字从 feature_dict 里找）
    if template is None:
        feature = self.feature_dict[category_name]
        template = feature.mat
    # 2. 确定搜索范围：若给了 box，就只在这块区域里找（大幅提速 + 减少误匹配）
    if box is not None:
        search_x1 = max(box.x, 0); search_y1 = max(box.y, 0)
        search_x2 = min(box.x + box.width, mat.shape[1])
        search_y2 = min(box.y + box.height, mat.shape[0])
    else:
        search_y2, search_x2 = mat.shape[:2]  # 没给范围就全图搜
    # 3. 从大图里切出搜索区域（numpy 切片，不复制数据，很快）
    search_area = mat[search_y1:search_y2, search_x1:search_x2, :3]
    # 4. ★ 核心：OpenCV 模板匹配，result 是一张「相似度热力图」
    result = cv2.matchTemplate(search_area, template, cv2.TM_CCOEFF_NORMED, mask=mask)
    np.nan_to_num(result, copy=False, nan=0, posinf=0, neginf=0)  # 把 NaN/无穷清 0，防污染
    # 5. 只取最像的一个（limit==1）：拿最大值和阈值比
    boxes = []
    if limit == 1 and match_method == cv2.TM_CCOEFF_NORMED:
        min_val, max_val, min_loc, max_loc = cv2.minMaxLoc(result)  # 找热力图最高分
        if max_val >= threshold:   # 分数够高才算匹配成功
            x, y = round(max_loc[0] / scale_factor) + search_x1, round(max_loc[1] / scale_factor) + search_y1
            boxes.append(Box(x, y, feature_width, feature_height, max_val, category_name))
    else:
        # 找所有超过阈值的点（如找全部相同按钮），并做非极大值抑制去重
        locations = filter_and_sort_matches(result, threshold, template.shape[1], template.shape[0])
        for loc in locations:
            x, y = round(loc[0][0] / scale_factor) + search_x1, round(loc[0][1] / scale_factor) + search_y1
            boxes.append(Box(x, y, feature_width, feature_height, loc[1], category_name))
        boxes = sort_boxes(boxes)
    return boxes   # 返回找到的所有 Box（含坐标+置信度）
💡 TM_CCOEFF_NORMED 是什么？ 这是归一化相关系数匹配法，结果范围 -1~1。1 表示完全相同，0 表示毫不相关，负数表示「反相」（颜色互补）。所以阈值一般设 0.9 以上。它抗亮度变化，是游戏匹配最常用的方法。

  1. 限定搜索区 box：不全屏搜，只搜按钮大概出现的区域，速度翻倍

8 第 8 章 🧩 BaseTask：把底层能力封装成「业务能用的积木」

前面几章拆的是「底层零件」。但业务开发者不该直接碰 BitBlt、PostMessage、matchTemplate——太繁琐。ok-script 用 BaseTask 把这些全封装好，你写业务时只需调 click / send_key / find_feature 这些「高层动作」。

Pythonok/task/task.py · click_box（「找到框并点击」的高层封装）
def click_box(self, box=None, relative_x=0.5, relative_y=0.5,
                  raise_if_not_found=False, move_back=False, move=True, down_time=0.01, after_sleep=1):
    # 支持传 Box 列表：取第一个
    if isinstance(box, list):
        if len(box) > 0:
            box = box[0]
    # 支持传字符串名字：自动查成 Box
    if isinstance(box, str):
        box = self.get_box_by_name(box)
    # 没找到框就报错/返回
    if not box:
        self.logger.error(f"click_box box is None")
        if raise_if_not_found:
            raise Exception(f"click_box box is None")
        return
    # 算出框内相对坐标（默认正中 0.5,0.5），再调底层 click
    x, y = box.relative_with_variance(relative_x, relative_y)
    return self.click(x, y, name=box.name, move_back=move_back, move=move,
                          down_time=down_time, after_sleep=after_sleep)

9 第 9 章 🔄 串起来：一句 click_box 背后发生了什么

现在把前 8 章的零件全串起来。当你在业务里写下 self.click_box("confirm_btn")，框架内部是这样一条流水线：

① 触发截图

BaseTask 调 capture.get_frame() → BitBlt 向游戏窗口 DC 请求像素，返回一帧 numpy 数组

② 取出模板

按名字 confirm_btn 从 FeatureSet.feature_dict 取出 Feature → 拿到模板图数组和它的坐标

③ 模板匹配

find_one_feature → cv2.matchTemplate 在大图里滑窗，算出相似度热力图，取峰值

④ 判定 + 定位

峰值 max_val >= threshold？→ 是则生成 Box(坐标, 置信度)，否则返回空（没找到）

⑤ 算点击点

box.relative_with_variance(0.5,0.5) → 算出框正中心的屏幕坐标

⑥ 后台点击

interaction.click(x,y) → 坐标转窗口客户区坐标，PostMessage 投递 WM_LBUTTONDOWN + WM_LBUTTONUP

⑦ 等待

after_sleep=1 → 睡 1 秒等界面响应，然后整个循环再来一遍（找下一个目标）

✎ 看懂这张图，你就看懂了 ok-script： 所谓「游戏自动化框架」，就是把上面这条流水线封装得足够好用、足够稳（后台、多分辨率、多线程、调试浮层都是围绕它做的增强）。所有复杂功能，剥开都是这个循环。

10 第 10 章 ✍️ 实战：基于框架，你自己能写出什么样的任务

理解了原理后，写业务其实很短。下面是一个「自动领取日常奖励」任务的示意代码——它调用的全是上面解析过的 BaseTask 方法：

Python你的第一个 ok-script 任务（示意，基于 BaseTask API）
from ok import og   # og 是框架的全局入口（ok-script 的惯例）

# 继承 BaseTask：白嫖 click/send_key/wait_scene 等全部能力
class DailyRewardTask(og.task.BaseTask):
    # 定义这个任务要用的模板图集合（对应 coco.json 里的标注）
    feature_set_names = ["daily_ui"]

    # 主逻辑：框架会反复调用 run，直到任务完成或退出
    def run(self):
        # 场景1：在主界面 → 点「日常」入口
        if self.click_box_if_name_match(self.find_feature("daily_entry"), "daily_entry"):
            self.sleep(1)          # 点完等界面加载
            return
        # 场景2：在日常面板 → 逐个领取奖励
        if self.click_box_if_name_match(self.find_feature("claim_btn"), "claim_btn"):
            self.sleep(0.5)
            return
        # 场景3：领完了 → 点关闭
        if self.click_box_if_name_match(self.find_feature("close_btn"), "close_btn"):
            self.stop()            # 任务完成，停止循环
            return
        # 都没匹配到：说明界面没按预期走，返回主界面重试
        self.send_key("esc")
💡 这段代码的精髓——「状态机」思想： 游戏界面是「状态」，每次截图识别出「当前在哪个状态」，就执行对应动作。run 被反复调用，界面一步步推进，直到完成。这就是所有游戏日常脚本的通用写法。
⚠️【真实项目的 70% 工作量在这】 代码框架就这么点，真正耗时的是：① 截大量模板图（每个按钮、每个界面）② 调阈值和搜索区 ③ 处理各种异常界面分支 ④ 多分辨率适配。这些是「脏活」，但理解了原理你都能搞定。
