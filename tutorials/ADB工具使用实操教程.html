1第 1 章 ADB 是什么与环境安装

1.1 ADB 是什么

ADB（Android Debug Bridge，安卓调试桥）是 Google 提供的命令行工具，是电脑与 Android 设备之间的「桥梁」。它让电脑能够：安装应用、传输文件、抓取日志、执行 Shell 命令、模拟操作等。对安卓测试而言，ADB 是使用频率最高的工具，没有之一。

核心概念：

  • ADB 采用 C/S（客户端/服务端）架构：你在命令行敲 adb 命令（客户端），后台有一个 adb server 负责与设备通信
  • 设备通过 USB（需开 USB 调试）或网络（无线 ADB）连接
  • 一条 adb 命令 = adb + 子命令 + 参数，如 adb install app.apk

1.2 安装 ADB（Windows）

  1. 下载 Android SDK Platform-Tools（含 adb），搜索官网下载，或安装任意安卓模拟器通常自带 adb
  2. 解压到固定目录，如 C:\platform-tools
  3. 配置环境变量：此电脑 → 属性 → 高级系统设置 → 环境变量 → Path → 新建 → 填入 C:\platform-tools
  4. 打开 cmd，输入 adb version，能看到版本号即安装成功
Shell / ADB
# 验证安装
adb version

# 查看帮助
adb help

1.3 开启手机 USB 调试

  1. 手机 设置 → 关于手机 → 连续点击「版本号」7 次，开启开发者模式
  2. 设置 → 系统 → 开发者选项 → 打开「USB 调试」
  3. 用数据线连电脑，手机弹窗「允许 USB 调试」点确定（勾选始终允许）
  4. 命令行执行 adb devices，能看到设备序列号 + device 字样即连接成功
【连不上排查】① 换数据线（有些线只能充电不能传数据）；② 确认 USB 调试已开；③ 手机弹窗是否点了允许；④ adb kill-server 再 adb start-server 重启服务。

✎ 实操练习 把自己的安卓手机（或启动一个模拟器）用 USB 连上电脑，执行 adb devices 确认能看到设备。

2第 2 章 设备连接与管理

2.1 查看设备

Shell / ADB
# 列出所有已连接设备
adb devices

# 显示更详细信息（含设备型号等）
adb devices -l

输出解读：

状态含义
device正常连接，可操作
unauthorized手机未点允许 USB 调试，去手机确认
offline设备离线，重插数据线或重启 adb 服务
no permissions驱动/权限问题（Windows 少见）

2.2 多设备时指定目标

当同时连了多台设备（如真机 + 模拟器），每条命令要用 -s 指定设备序列号，否则报错 more than one device：

Shell / ADB
# 指定序列号操作
adb -s emulator-5554 shell
adb -s 192.168.1.100:5555 install app.apk

# 序列号就是 adb devices 里显示的那串

2.3 无线 ADB（真机远程连接）

不想插线时，可用 WiFi 连接（手机和电脑需在同一网络）：

Shell / ADB
# 方式一：先用 USB 连一次，再切无线
adb tcpip 5555
adb connect 192.168.1.100:5555
adb disconnect 192.168.1.100:5555   # 断开

# 方式二：Android 11+ 无线调试
# 开发者选项 → 无线调试 → 用配对码配对设备 → 填入 IP 和端口
【无线连接失败】确认手机和电脑在同一 WiFi；防火墙可能拦截 5555 端口；重新 adb connect。

2.4 重启与基础控制

Shell / ADB
adb reboot                 # 重启设备
adb reboot bootloader          # 重启到 bootloader
adb reboot recovery            # 重启到 recovery
adb shell reboot -p            # 关机
adb shell input keyevent 26    # 模拟按电源键

✎ 实操练习 执行 adb devices -l 查看设备详细信息；如果有两台设备，用 -s 分别对它们执行 shell 命令。

3第 3 章 应用管理（安装/卸载/启动）

3.1 安装与卸载

Shell / ADB
# 安装 apk
adb install app.apk
adb install -r app.apk          # -r 覆盖安装（保留数据）
adb install -t app.apk          # 允许测试包
adb install -d app.apk          # 允许降级安装
adb install -g app.apk          # 授予所有运行时权限

# 卸载
adb uninstall com.example.app              # 卸载
adb uninstall -k com.example.app           # 保留数据和缓存(-k)
【安装失败常见码】Failure [INSTALL_FAILED_...]：OLD_VERSION 版本更高需 -d；UPDATE_INCOMPATIBLE 签名不一致需先卸载；INSUFFICIENT_STORAGE 存储不足。

3.2 查看已安装应用与包名

Shell / ADB
# 列出所有已安装应用包名
adb shell pm list packages

# 过滤找目标应用包名
adb shell pm list packages | grep game
adb shell pm list packages -3        # 只看第三方应用

3.3 启动/停止应用

Shell / ADB
# 启动应用（需知道包名和 Activity）
adb shell am start -n com.example.app/.MainActivity

# 用包名启动（自动找入口 Activity）
adb shell monkey -p com.example.app -c android.intent.category.LAUNCHER 1

# 强制停止应用
adb shell am force-stop com.example.app

# 清除应用数据
adb shell pm clear com.example.app

3.4 查看当前前台应用

Shell / ADB
# 查看当前栈顶的 Activity（找包名/Activity 很有用）
adb shell dumpsys activity activities | findstr mResumedActivity
# Mac/Linux 用 grep 替代 findstr

✎ 实操练习 安装一个游戏 App，用 pm list packages 找到它的包名，再用 am start 启动它，最后用 am force-stop 关闭。

4第 4 章 文件传输

4.1 pull 与 push

pull 从设备拉到电脑，push 从电脑推到设备，方向相反，语法一致：

Shell / ADB
# pull：设备 → 电脑
adb pull /sdcard/Download/file.txt ./
adb pull /sdcard/Android/data/com.example.app ./logs

# push：电脑 → 设备
adb push app.apk /sdcard/Download/
adb push ./config.json /sdcard/
【路径方向】pull 是「设备路径 本地路径」，push 是「本地路径 设备路径」——顺序正好相反，别搞混。

4.2 常用目录

目录说明
/sdcard/外部存储根目录（下载、图片等）
/sdcard/Download/下载目录
/sdcard/Android/data/包名/App 的外部数据目录（日志常在这）
/data/data/包名/App 私有目录（需 root 或 run-as）
/data/tombstones/崩溃堆栈文件（需 root）

4.3 拉取 App 私有目录日志

很多 App 把日志写在私有目录，普通 pull 无权限，用 run-as（仅 debug 包有效）：

Shell / ADB
# 列出私有目录文件
adb shell run-as com.example.app ls files/

# 拉取私有目录日志
adb pull /data/data/com.example.app/files/app.log ./

# 若无 root，可先 cat 出来重定向
cat &gt; app.log &lt;&lt; EOF
$(adb shell run-as com.example.app cat files/app.log)
EOF

✎ 实操练习 用 push 把一个文本文件推到手机 /sdcard/，再用 pull 把它拉回电脑另一个目录，验证内容一致。

5第 5 章 日志抓取（logcat 核心）

这是 ADB 对测试最重要的能力。logcat 抓取设备系统与应用日志，是定位崩溃、异常的第一手段。

5.1 基础用法

Shell / ADB
adb logcat                        # 实时查看全部日志（刷屏，Ctrl+C 停止）
adb logcat -d                     # 打印后退出（适合存文件）
adb logcat -c                     # 清空日志缓冲（复现前先清）
adb logcat -v time                # 显示时间戳
adb logcat *:E                    # 只看 Error 及以上级别

5.2 日志级别

级别值说明
V (Verbose)2所有信息，最详细
D (Debug)3调试信息
I (Info)4一般信息
W (Warning)5警告
E (Error)6错误
F (Fatal)7致命错误（崩溃）
S (Silent)8静默，不输出

过滤时用 *:E 表示只显示 E 及以上（E、F）。

5.3 过滤与筛选

Shell / ADB
# 按 Tag 过滤（App 自定义的日志标签）
adb logcat -s MyTag
adb logcat -s Tag1 Tag2

# 按关键字过滤（配合系统 grep / findstr）
adb logcat | grep &#x27;MyApp&#x27;                 # Mac/Linux
adb logcat | grep -iE &#x27;error|exception|crash&#x27;
adb logcat | findstr &quot;crash&quot;              # Windows cmd

# 显示匹配行前后文（崩溃定位必备）
adb logcat | grep -A20 &#x27;FATAL EXCEPTION&#x27;

5.4 导出日志到文件

Shell / ADB
# 抓完即退出，存文件
adb logcat -d &gt; app_log.txt

# 标准复现流程：清缓冲 → 复现 → 导出
adb logcat -c
# （在 App 里操作触发问题）
adb logcat -d &gt; bug.log

5.5 定位崩溃

Shell / ADB
# 抓崩溃堆栈
adb logcat *:E | grep -A30 &#x27;FATAL EXCEPTION&#x27;
adb logcat | grep -iE &#x27;AndroidRuntime|CRASH|SIGSEGV&#x27;

# 只看某进程的日志（先拿 pid）
adb shell pidof com.example.app
adb logcat --pid=12345
【复现崩溃标准动作】① adb logcat -c 清缓冲 → ② 操作 App 触发崩溃 → ③ adb logcat -d > crash.log 一次性导出。这样日志干净，全是本次崩溃相关，提单时直接附上。

✎ 实操练习 清缓冲后打开一个 App 触发一次崩溃（或随便操作），导出日志到 crash.log，用 grep 找出 FATAL EXCEPTION 及其后 20 行堆栈。

6第 6 章 设备 Shell 与系统调试

6.1 进入设备 Shell

Shell / ADB
# 进入交互式 shell
adb shell

# 直接执行单条命令
adb shell getprop ro.build.version.release   # 查安卓版本
adb shell getprop ro.product.model           # 查机型
adb shell whoami                               # 当前用户
adb shell exit                                 # 退出

6.2 进程与性能

Shell / ADB
# 查看进程
adb shell ps | grep MyApp
adb shell pidof com.example.app

# 查看内存/资源
adb shell dumpsys meminfo com.example.app    # 内存详情
adb shell dumpsys cpuinfo                     # CPU 占用
adb shell top -n 1                            # 快照式 top

6.3 屏幕操作与截图录屏

Shell / ADB
# 截图
adb shell screencap /sdcard/screen.png
adb pull /sdcard/screen.png ./

# 一行搞定截图到电脑（Mac/Linux）
adb exec-out screencap -p &gt; screen.png

# 录屏（Ctrl+C 停止）
adb shell screenrecord /sdcard/demo.mp4
adb pull /sdcard/demo.mp4 ./

6.4 模拟输入操作

Shell / ADB
# 模拟点击（坐标）
adb shell input tap 500 800

# 模拟滑动
adb shell input swipe 300 1000 300 300 300

# 模拟按键（24=音量+，25=音量-，26=电源，4=返回，3=Home）
adb shell input keyevent 26

# 模拟输入文本
adb shell input text hello
【用途】模拟操作常用于自动化测试、批量点击、复现特定手势问题。坐标可用开发者选项里的「指针位置」查看。

6.5 端口转发（辅助抓包）

Shell / ADB
# 让手机流量经电脑代理（抓包辅助）
adb reverse tcp:8888 tcp:8888
# 这样手机访问 127.0.0.1:8888 会转到电脑的 8888 端口
adb reverse --list          # 查看转发
adb reverse --remove-all    # 清除

✎ 实操练习 对手机截图并拉到电脑；用 input tap 在屏幕上点一下；用 screenrecord 录 5 秒屏并拉回。

7第 7 章 ADB 能力边界与联合使用

7.1 ADB 能做什么、不能做什么

能力ADB 能否说明
抓客户端日志✅ 主力logcat 抓系统/应用日志，pull 拉日志文件
安装/卸载应用✅ 主力install / uninstall
文件传输✅ 主力pull / push
模拟操作✅ 可以input tap/swipe/keyevent
辅助抓包⚠️ 仅辅助reverse 端口转发，抓包仍靠 Fiddler/Wireshark
抓网络包内容❌ 不能需 Wireshark/tcpdump（adb shell tcpdump 需 root）
看服务器报错❌ 不能服务器是远程机器，ADB 够不到，需 SSH

7.2 三把钥匙开三扇门

记住这个测试定位的核心框架：

  • ADB 管设备 —— 装包、抓客户端日志、传文件、模拟操作
  • 抓包工具管网络 —— Fiddler/Wireshark 看客户端与服务器往来的数据
  • SSH 管服务器 —— 登录服务器看后端 error 日志

三者互补：ADB 看客户端内部、抓包看网络链路、SSH 看服务器内部，联合使用才能完整定位问题。

7.3 实战：一次完整的崩溃定位流程

  1. adb logcat -c 清空日志缓冲
  2. 操作 App 触发崩溃
  3. adb logcat -d > crash.log 导出日志
  4. grep -A30 'FATAL EXCEPTION' crash.log 找崩溃堆栈
  5. 看异常类型（如 NullPointerException）+ 首个业务代码行号
  6. 若崩溃前有网络请求，再用 Fiddler 抓包看接口是否异常
  7. 整理堆栈 + 抓包截图，提 Bug 单给开发

✎ 实操练习 完整走一遍 7.3 的流程：清缓冲 → 触发崩溃 → 导出 → 定位堆栈 → 判断是客户端还是网络问题。

9高频问题排查

现象原因解决
adb devices 看不到设备USB 调试未开/线不行开 USB 调试、换数据线、点允许、重启 adb 服务
unauthorized手机未授权手机弹窗点允许，勾选始终允许
offline连接不稳定重插数据线、adb kill-server 重启
more than one device多设备未指定用 -s 序列号指定目标
安装失败 Failure版本/签名/存储看失败码，-r 覆盖 / -d 降级 / 先卸载
logcat 刷屏太快日志量大加过滤：*:E 或 | grep 关键字
pull 私有目录失败无权限用 run-as（debug 包）或 root
无线 connect 失败不同网段/防火墙确认同 WiFi，放行 5555 端口
