1 pytest 是什么？为什么用它？

pytest 是 Python 生态中最流行的测试框架，比 unittest 更简洁、更强大。它不需要继承类，用普通函数就能写测试，自动发现用例，还支持 fixture 依赖注入、参数化、插件生态等高级功能。

💡 一句话总结： pytest = 用函数写测试 + 自动发现 + fixture 注入 + 丰富插件。
特性unittestpytest
测试用例继承 unittest.TestCase普通函数 def test_xxx():
断言self.assertEqual(a, b)原生 assert a == b
FixturesetUp/tearDown 方法函数参数注入，scope 灵活
参数化需 ddt 等第三方库内置 @pytest.mark.parametrize
用例发现手动或 Loader自动扫描 test_*.py
插件生态有限700+ 插件（cov / mock / xdist 等）

核心概念速览

概念一句话解释类比
Test Case一个 def test_ 开头的函数一条测试用例
Fixture测试的「前置条件」，自动注入测试数据 + 环境准备
Parametrize一组数据跑同一个测试逻辑数据驱动测试
Marker给测试打标签（skip / slow / smoke）用例分类标签
conftest.py共享 fixture 的配置文件公共测试基础设施

3.4 测试一个真实函数

实际工作中，我们测试的是业务函数，不是简单的算术。下面演示如何测试一个计算器模块：

calculator.py — 被测业务代码
"""一个简单的计算器模块"""

def add(a, b):
    """加法"""
    return a + b

def divide(a, b):
    """除法（含除零检查）"""
    if b == 0:
        raise ValueError("除数不能为零")
    return a / b

def is_even(n):
    """判断偶数"""
    return n % 2 == 0
test_calculator.py — 测试代码
import pytest
from calculator import add, divide, is_even

def test_add_positive():
    assert add(1, 2) == 3

def test_add_negative():
    assert add(-1, 2) == 1

def test_divide_normal():
    assert divide(10, 2) == 5.0

def test_divide_by_zero():
    with pytest.raises(ValueError, match="除数不能为零"):
        divide(10, 0)

def test_is_even_true():
    assert is_even(4) is True

def test_is_even_false():
    assert is_even(7) is False
⚠️ 常见坑： 测试文件里 import 业务模块时，确保被测模块在 sys.path 中。如果报 ModuleNotFoundError，在项目根目录运行 python -m pytest，或加 --import-mode=importlib。

4 Fixture — pytest 的核心武器

Fixture 是 pytest 最强大的特性。它让你把「准备测试数据」「搭建环境」「清理资源」从测试逻辑中分离出来，通过函数参数自动注入。

4.1 基础用法：setup + teardown

test_fixture_demo.py
import pytest

# 最简单的 fixture：用 yield 实现 setup/teardown
@pytest.fixture
def db_connection():
    """模拟数据库连接"""
    # ── setup（yield 之前）──
    print("\n🔗 正在连接数据库...")
    conn = {"status": "connected"}

    yield conn  # ← 把 conn 注入到测试函数

    # ── teardown（yield 之后）──
    print("\n🔌 正在关闭数据库连接...")

# 测试函数通过参数名接收 fixture
def test_db_query(db_connection):
    print(f"\n📊 使用连接: {db_connection}")
    assert db_connection["status"] == "connected"
🔑 yield 机制： yield 之前 = setup，yield 之后 = teardown。测试函数通过参数名接收 fixture 返回值。

4.2 Fixture 的四种 scope

scope 控制 fixture 执行几次——选对 scope 能大幅提升测试速度。

scope执行次数适用场景示例
function（默认）每个测试函数执行一次测试数据、临时状态用户对象、列表
class每个测试类执行一次类级别共享资源测试客户端
module每个 .py 文件执行一次模块级配置数据库配置
session整个测试会话执行一次昂贵资源、全局配置数据库连接池、API 客户端
scope 示例
import pytest

@pytest.fixture(scope="function")  # 默认，每个 test 函数执行一次
def fresh_list():
    return []

@pytest.fixture(scope="module")  # 每个 .py 文件只执行一次
def db_config():
    print("🔧 加载数据库配置（模块级）")
    return {"host": "localhost", "port": 3306}

@pytest.fixture(scope="session")  # 整个测试会话只执行一次
def api_client():
    print("🚀 创建 API 客户端（会话级）")
    client = {"base_url": "https://api.example.com"}
    yield client
    print("🔚 关闭 API 客户端")

4.3 Fixture 嵌套依赖

Fixture 可以依赖另一个 fixture，形成依赖链——这是 pytest 最优雅的设计之一。

fixture 嵌套示例
@pytest.fixture
def db_config():
    """数据库配置"""
    return {"host": "localhost", "port": 3306}

@pytest.fixture
def db_connection(db_config):  # ← 依赖 db_config
    """数据库连接（依赖配置）"""
    print(f"\n🔗 连接 {db_config['host']}:{db_config['port']}")
    conn = {"status": "connected"}
    yield conn
    print("\n🔌 关闭连接")

@pytest.fixture
def db_cursor(db_connection):  # ← 依赖 db_connection
    """数据库游标（依赖连接）"""
    print("\n📝 创建游标")
    cursor = {"type": "readwrite"}
    yield cursor
    print("\n📝 关闭游标")

def test_query(db_cursor):
    print(f"\n📊 使用游标: {db_cursor}")
    assert db_cursor["type"] == "readwrite"
📊 执行顺序： db_config → db_connection → db_cursor → test_query → db_cursor teardown → db_connection teardown

4.4 autouse — 自动执行的 fixture

加 autouse=True 后，fixture 会在每个测试中自动执行，无需显式声明参数。

autouse 示例
@pytest.fixture(autouse=True)
def reset_state():
    """每个测试前后自动重置状态"""
    print("\n🔄 [autouse] 测试前：重置状态")
    yield
    print("\n🔄 [autouse] 测试后：清理状态")

def test_a():
    pass  # 会自动打印重置信息

def test_b():
    pass  # 同样自动执行
⚠️ autouse 慎用： autouse fixture 会让测试「看起来独立但实际共享状态」，排查失败时容易困惑。新手建议显式声明参数，可读性更好。

5 断言 — 用原生 assert

pytest 不需要 assertEqual、assertTrue 等方法，直接用 Python 原生 assert 语句。pytest 会自动增强断言信息，失败时给出清晰的对比。

test_assertions.py
def test_equality():
    assert 1 + 1 == 2
    assert "hello" == "hello"

def test_inequality():
    assert 1 != 2
    assert 10 > 5
    assert 5 <= 10

def test_truthiness():
    assert True
    assert bool([1, 2, 3])  # 非空列表为 True
    assert not bool([])        # 空列表为 False

def test_membership():
    assert 1 in [1, 2, 3]
    assert "key" in {"key": "value"}
    assert "world" not in "hello"

def test_type():
    assert isinstance(42, int)
    assert isinstance("hello", str)

def test_exception():
    with pytest.raises(ValueError):
        raise ValueError("出错了")

def test_exception_with_message():
    with pytest.raises(ValueError, match="出错了"):
        raise ValueError("出错了")

def test_approximate():
    assert 3.14159 == pytest.approx(3.14, rel=1e-2)
💡 断言失败时的输出： pytest 会自动展示 assert 表达式的详细对比，无需手动格式化错误信息。
失败输出示例
# AssertionError: assert 4 == 5
#
#   - 4
#   + 5

6 参数化 — 一组数据跑同一逻辑

参数化是 pytest 的数据驱动测试能力。用一组数据跑同一个测试逻辑，自动生成多个用例。这是测试工程师最常用的功能之一。

6.1 基础参数化

test_parametrize.py
import pytest
from calculator import add

# 基础用法：参数名 → 数据列表
@pytest.mark.parametrize(
    "a, b, expected",      # ← 参数名（逗号分隔）
    [
        (1, 2, 3),         # ← 第一组数据
        (0, 0, 0),
        (-1, 1, 0),
        (100, 200, 300),
    ]
)
def test_add(a, b, expected):
    assert add(a, b) == expected
✅ 运行结果： 一个 @parametrize 生成 4 个测试用例，pytest -v 会显示：
test_add[1-2-3] PASSED
test_add[0-0-0] PASSED
test_add[-1-1-0] PASSED
test_add[100-200-300] PASSED

6.2 自定义测试 ID

默认 ID 不够直观？用 ids 参数自定义名称：

自定义 ID
@pytest.mark.parametrize(
    "input, expected",
    [
        ("hello", "HELLO"),
        ("world", "WORLD"),
        ("", ""),
    ],
    ids=["正常字符串", "正常字符串2", "空字符串"]  # ← 自定义名称
)
def test_upper(input, expected):
    assert input.upper() == expected

6.3 多维度组合（笛卡尔积）

多个 @parametrize 叠加 = 笛卡尔积组合：

笛卡尔积组合
# 3 × 2 = 6 种组合
@pytest.mark.parametrize("a", [1, 2, 3])
@pytest.mark.parametrize("b", [10, 100])
def test_multiply(a, b):
    print(f"a={a}, b={b}, result={a * b}")

6.4 实战：游戏测试场景

假设你在测试《天龙》游戏的伤害计算，参数化可以这样用：

游戏伤害测试示例
@pytest.mark.parametrize(
    "attack, defense, expected_damage",
    [
        # (攻击力, 防御力, 预期伤害)
        (100, 0, 100),       # 无防御
        (100, 50, 50),       # 防御减半
        (100, 100, 0),       # 防御抵消
        (0, 100, 0),         # 攻击为0
        (100, -10, 110),     # 负防御（增伤）
    ],
    ids=["无防御", "防御减半", "完全抵消", "零攻击", "负防御增伤"]
)
def test_damage_calc(attack, defense, expected_damage):
    """测试伤害计算公式"""
    damage = calculate_damage(attack, defense)
    assert damage == expected_damage

7 Markers — 给测试打标签

Marker 是给测试用例分类的标签。你可以按「冒烟测试」「回归测试」「慢速测试」等维度筛选运行。

7.1 内置 Markers

test_markers.py
import pytest

@pytest.mark.skip(reason="暂时跳过")
def test_broken():
    pass  # 跳过

@pytest.mark.skipif(True, reason="条件不满足时跳过")
def test_conditional():
    pass

@pytest.mark.xfail(reason="已知会失败")
def test_expected_fail():
    assert False  # 预期失败，不算错误

@pytest.mark.xfail(strict=True)
def test_strict_xfail():
    pass  # strict=True 时，如果测试通过了反而报错

@pytest.mark.timeout(5)  # 需要 pytest-timeout 插件
def test_slow():
    pass

7.2 自定义 Markers

在 pyproject.toml 中注册自定义 marker，避免拼写警告：

pyproject.toml
[tool.pytest.ini_options]
markers = [
    "smoke: 冒烟测试用例",
    "regression: 回归测试用例",
    "slow: 耗时较长的测试",
    "P0: 最高优先级",
    "P1: 高优先级",
    "P2: 中优先级",
]

7.3 按 Marker 筛选运行

终端
# 只运行冒烟测试
python -m pytest -m smoke

# 运行 P0 优先级
python -m pytest -m P0

# 运行 P0 或 P1
python -m pytest -m "P0 or P1"

# 排除慢速测试
python -m pytest -m "not slow"

# 冒烟 + 非慢速
python -m pytest -m "smoke and not slow"
💡 游戏测试实践： 用 marker 区分「每日冒烟」「版本回归」「边界专项」，CI 中按标签触发不同流水线。

8 conftest.py — 共享 Fixture 配置

conftest.py 是 pytest 的配置文件，放在项目根目录或任意子目录中。同目录及子目录的测试文件可以自动使用其中定义的 fixture，无需 import。

8.1 项目结构推荐

目录结构
my_project/
├── src/                     # 业务代码
│   └── calculator.py
├── tests/                   # 测试目录
│   ├── conftest.py          # ← 共享 fixture
│   ├── test_calculator.py
│   └── test_utils.py
├── pyproject.toml
└── README.md

8.2 conftest.py 示例

tests/conftest.py
"""共享 fixture 配置"""
import pytest

@pytest.fixture
def sample_player():
    """示例玩家数据"""
    return {
        "name": "测试玩家",
        "level": 50,
        "hp": 1000,
        "mp": 500,
    }

@pytest.fixture
def sample_enemies():
    """示例怪物列表"""
    return [
        {"name": "小怪", "hp": 100},
        {"name": "精英怪", "hp": 500},
        {"name": "BOSS", "hp": 2000},
    ]

@pytest.fixture(scope="session")
def game_config():
    """游戏全局配置（会话级）"""
    return {
        "server": "test-server",
        "version": "1.0.0",
    }

10 3 天快速学习路径

第 1 天：基础入门（2-3 小时）

目标：能独立写测试、运行测试、看懂输出。

  1. 安装 pytest

    pip install pytest，验证 python -m pytest --version

  2. 写 3 个简单测试

    创建 test_demo.py，写 test_addition、test_string、test_list，运行并看懂输出。

  3. 测试一个业务函数

    写 calculator.py（add/divide/is_even），再写对应的测试，包含正常值和异常值。

  4. 练习 assert

    用各种 assert 写法：==、!=、in、isinstance、pytest.raises、pytest.approx。

  5. 用 -v 和 -x 运行

    对比 pytest、pytest -v、pytest -x 的输出差异。

第 2 天：核心进阶（3-4 小时）

目标：掌握 fixture 和参数化，能写结构化的测试。

  1. Fixture 基础

    用 yield 写 setup/teardown，理解 fixture 通过参数注入。

  2. Fixture scope

    对比 function / module / session 三种 scope 的执行次数差异。

  3. Fixture 嵌套

    写一个 3 层嵌套的 fixture 链（config → connection → cursor），观察执行顺序。

  4. Parametrize 基础

    用 @pytest.mark.parametrize 改造之前的 test_add，传入 5 组数据。

  5. Parametrize + ids

    给参数化用例加自定义 ID，让 -v 输出更清晰。

  6. conftest.py

    把公共 fixture 移到 conftest.py，在另一个测试文件中验证自动可用。

第 3 天：实战应用（3-4 小时）

目标：能组织项目级测试，会用 marker 和覆盖率。

  1. Markers 分类

    注册 smoke / regression / P0 等 marker，给已有用例打标签，用 -m 筛选运行。

  2. 项目结构搭建

    按标准结构组织代码：src/ + tests/ + conftest.py + pyproject.toml。

  3. 覆盖率报告

    安装 pytest-cov，运行 --cov=src --cov-report=html，打开 HTML 报告看覆盖率。

  4. 综合练习

    为一个真实业务模块写完整测试：正常流 + 异常流 + 边界值 + 参数化。

# user_validator.py
import re

def validate_username(username):
    if not (3 <= len(username) <= 20):
        return False
    if username[0] == "_" or username[-1] == "_":
        return False
    return bool(re.match(r'^[a-zA-Z0-9_]$', username))

        ("12345", True),     # 纯数字
        ("user@name", False),  # 特殊字符
    ]
)
def test_validate_username(username, expected):
    assert validate_username(username) == expected
练习 2：背包物品管理（中级）

需求：实现一个 Backpack 类，支持以下操作：

  • add_item(name, weight) — 添加物品
  • remove_item(name) — 移除物品
  • get_total_weight() — 获取总重量
  • has_item(name) — 检查是否有某物品
  • 背包有最大承重 max_weight，超重时 add_item 抛出 ValueError

要求：用 fixture 创建背包实例，测试添加、移除、超重、空背包等场景。

参考答案
# backpack.py
class Backpack:
    def __init__(self, max_weight):
        self.max_weight = max_weight
        self.items = {}  # {name: weight}

    def add_item(self, name, weight):
        if self.get_total_weight() + weight > self.max_weight:
            raise ValueError(f"超重！当前 {self.get_total_weight()} + {weight} > {self.max_weight}")
        self.items[name] = weight

    def remove_item(self, name):
        if name not in self.items:
            raise KeyError(f"物品 '{name}' 不存在")
        del self.items[name]

    def get_total_weight(self):
        return sum(self.items.values())

    def has_item(self, name):
        return name in self.items

# test_backpack.py
import pytest
from backpack import Backpack

@pytest.fixture
def backpack():
    return Backpack(max_weight=100)

def test_add_single_item(backpack):
    backpack.add_item("剑", 30)
    assert backpack.has_item("剑")
    assert backpack.get_total_weight() == 30

def test_add_multiple_items(backpack):
    backpack.add_item("剑", 30)
    backpack.add_item("盾", 20)
    backpack.add_item("药水", 5)
    assert backpack.get_total_weight() == 55

def test_remove_item(backpack):
    backpack.add_item("剑", 30)
    backpack.remove_item("剑")
    assert not backpack.has_item("剑")

def test_remove_nonexistent(backpack):
    with pytest.raises(KeyError):
        backpack.remove_item("不存在的物品")

def test_overweight(backpack):
    backpack.add_item("重甲", 80)
    with pytest.raises(ValueError, match="超重"):
        backpack.add_item("盾牌", 30)  # 80+30 > 100

def test_empty_backpack(backpack):
    assert backpack.get_total_weight() == 0
    assert len(backpack.items) == 0
练习 3：技能伤害计算器（高级）

需求：模拟一个游戏技能伤害计算系统：

  • 基础伤害 = 攻击力 × 技能倍率
  • 暴击时伤害 ×1.5
  • 防御减伤 = 防御力 × 0.5（最低减到 0）
  • 最终伤害 = max(基础伤害 - 防御减伤, 1) × (1.5 if 暴击 else 1)

要求：用 fixture 创建角色属性，参数化覆盖不同攻击/防御/暴击组合，用 marker 区分 P0/P1 优先级。

参考答案
# damage_calculator.py
def calculate_damage(attack, skill_multiplier, defense, is_crit):
    base_damage = attack * skill_multiplier
    defense_reduction = min(defense * 0.5, base_damage)
    damage_after_defense = max(base_damage - defense_reduction, 1)
    if is_crit:
        damage_after_defense *= 1.5
    return round(damage_after_defense, 2)

# test_damage.py
import pytest
from damage_calculator import calculate_damage

@pytest.fixture
def warrior():
    return {"attack": 100, "defense": 30}

@pytest.fixture
def mage():
    return {"attack": 80, "defense": 15}

@pytest.mark.parametrize(
    "char, multiplier, is_crit, expected",
    [
        (warrior, 1.0, False, 85.0),   # 100*1 - 30*0.5 = 85
        (warrior, 1.0, True, 127.5),   # 85 * 1.5
        (warrior, 2.0, False, 185.0),  # 200 - 15 = 185
        (mage, 1.5, False, 112.5),     # 120 - 7.5 = 112.5
        (mage, 1.5, True, 168.75),     # 112.5 * 1.5
    ],
    ids=["战士普攻", "战士暴击", "战士2倍技", "法师普攻", "法师暴击"]
)
def test_damage_basic(char, multiplier, is_crit, expected):
    damage = calculate_damage(
        attack=char["attack"],
        skill_multiplier=multiplier,
        defense=char["defense"],
        is_crit=is_crit
    )
    assert damage == expected

@pytest.mark.P0
def test_min_damage_is_1():
    """即使攻击远低于防御，伤害最低为1"""
    damage = calculate_damage(attack=1, skill_multiplier=1.0, defense=100, is_crit=False)
    assert damage == 1
