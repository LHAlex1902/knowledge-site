1 第 1 章 🤖 认识 UI 自动化测试

1.1 📌 一句话认识

UI 自动化测试，就是用代码模拟人在浏览器上的操作——打开页面、点击按钮、输入文本、选择下拉框，然后核对页面显示是否符合预期。它测的是用户真实能看到的界面与交互。

💡 一句话总结： UI 自动化 = 用脚本驱动浏览器做操作 + 自动断言页面结果，把「重复的界面点击验证」交给程序。

1.2 🎯 UI 自动化 vs 接口自动化

对比维度UI 自动化接口自动化
测试层面用户界面与交互后端业务逻辑
执行速度慢（要渲染、等待）快（毫秒级）
稳定性易受页面改版影响接口契约较稳定
维护成本较高较低
覆盖场景交互流程、页面展示数据正确性
🔑 知识点 · 测试金字塔： 理想的测试结构是「大量接口测试（底层、快、稳）+ 适量 UI 测试（顶层、慢、覆盖关键交互）」。UI 自动化不该追求全覆盖，只覆盖核心主流程和高价值交互，否则维护成本会压垮团队。

6 第 6 章 ⏳ 等待机制（攻克 UI 自动化最大难点）

UI 脚本 80% 的不稳定都来自「元素还没加载就去找它」。等待机制就是让脚本「等元素真正可用了再操作」，是 UI 自动化从 flaky 到稳定的关键。

8 第 8 章 🏛️ PO 页面对象模式（可维护的核心）

如果每个用例都直接写一堆 find_element + click，页面一改定位全崩。PO（Page Object）模式把「每个页面」封装成一个类，页面元素定位和操作方法集中在类里，用例只调方法——页面变了只改类，用例不动。

8.1 🔄 PO 模式的核心思想

页面 → 封装成类
→
元素定位集中在类里
→
用例只调类的方法
→
页面改动只改类
🔑 知识点 · PO 模式： Page Object。一个页面对应一个类，类里放该页面的元素定位（属性）和操作动作（方法，如 login()）。用例层不碰 find_element，只调 login_page.login()。好处：定位与用例解耦，页面改版只改页面对象类，用例几乎不动。

1什么是 UI 自动化测试？它适合测什么？基础
回答要点

2Selenium 的 WebDriver 原理是什么？原理
回答要点
客户端-服务器模型 + 通过浏览器驱动通信 + 翻译指令。
参考答案
WebDriver 采用 C/S 模型：Python 脚本是客户端，浏览器驱动（如 chromedriver）是服务端。脚本发出 click/send_keys 等指令，驱动翻译成浏览器能执行的动作并返回结果。Selenium 4 内置 Selenium Manager 自动管理驱动版本。
回答红线
不要说「Selenium 直接操作浏览器内核」——中间隔着浏览器驱动这一层。
3Selenium 有哪些元素定位方式？你优先用哪个？定位
回答要点
列 8 种 + 优先级 id>CSS>name>XPath。
参考答案
8 种：ID、NAME、CLASS、TAG_NAME、LINK_TEXT、PARTIAL_LINK_TEXT、XPATH、CSS_SELECTOR。优先用 ID（唯一最快），其次 CSS_SELECTOR（性能好），按文字找按钮用 XPath，class/tag 只在唯一时用。
回答红线
不要说「XPath 最好用」——它功能强但对结构敏感、性能不如 CSS，应作为兜底。
4find_element 和 find_elements 的区别？定位
回答要点
单数返回第一个/抛异常，复数返回列表。
参考答案
find_element 返回第一个匹配元素，找不到抛 NoSuchElementException；find_elements 返回所有匹配元素的列表，找不到返回空列表。取唯一元素用单数，取一组用复数。
回答红线
不要以为 find_element 找不到返回 None——它抛异常，需 try/except 或配合等待。
5为什么 UI 脚本经常「时过时不过」？怎么解决？等待
回答要点
元素加载时序 + 缺等待 + 用显式等待。
参考答案
UI 元素常异步加载，脚本执行快于页面渲染，导致找元素时它还没出现。解决：用显式等待 WebDriverWait 等元素可见/可点击再继续，配合隐式等待兜底，避免 time.sleep 死等。
回答红线
不要回答「加 time.sleep(3) 就行」——死等慢且不可靠，是反模式。
6隐式等待和显式等待的区别？等待
回答要点
作用范围 + 灵活性 + 各自用法。
参考答案
隐式等待 implicitly_wait 全局设置，每次 find 自动等待超时；显式等待 WebDriverWait 针对具体元素/条件（可见、可点击），until 条件成立或超时。显式更精准灵活，是首选；隐式作全局兜底。
回答红线
不要说「二者一样，用哪个都行」——显式能等特定条件，隐式只能等元素出现。

presence/visibility/clickable/title_contains。
参考答案
presence_of_element_located（在 DOM）、visibility_of_element_located（可见有宽高）、element_to_be_clickable（可点击）、title_contains（标题含关键字）、frame_to_be_available_and_switch（iframe 可用）。优先等可见/可点击而非仅存在。
回答红线
不要只等 presence 就去 click——元素在 DOM 里不代表可见可点。
8什么是 PO 模式？有什么好处？架构

页面对象 + 定位与用例分离 + 改版只改类。
参考答案
PO（Page Object）把每个页面封装成类，元素定位和操作集中在类里，用例只调类方法。好处：定位与用例解耦，页面改版只改页面对象类，用例几乎不动，大幅提升可维护性。
回答红线
不要说「PO 就是多写几个类」——核心是定位与用例解耦带来的可维护性。

不要用绝对 XPath——极脆弱，几乎必被页面改动破坏。

22conftest.py 里 driver fixture 的 scope 怎么选？工程
回答要点
function 隔离性好 / session 快但共享状态。
参考答案

回答红线
不要为省时间用 session 级共享浏览器——登录态/数据会互相污染。
