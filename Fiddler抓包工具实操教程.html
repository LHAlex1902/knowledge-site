1半天学习路线（约 3.5 小时）

本教程按半天设计，共 6 个模块，每个模块「学完即练」。建议严格按顺序推进，因为后面的模块依赖前面的配置。

时段模块学完你能做到时长
第1节模块1 安装与界面装好 Fiddler，认识主界面 5 大区域30 分钟
第2节模块2 HTTPS 解密攻克证书，看到 HTTPS 明文（核心难点）45 分钟
第3节模块3 抓包与过滤抓到请求，用过滤器快速定位目标接口30 分钟
第4节模块4 断点与重放拦截改包、重放请求做边界测试30 分钟
第5节模块5 FiddlerScript写简单规则做自动改写/Mock30 分钟
第6节模块6 移动端抓包手机连代理抓 App 包（安卓/iOS）25 分钟
【准备清单】一台可联网电脑（Windows 最佳，Fiddler 原生支持）；一台安卓手机或模拟器 + 一台 iOS 真机（做移动端抓包用）；手机与电脑能连同一 WiFi。

2模块 1 安装与界面导览

1.1 安装 Fiddler

  1. 官网下载：搜索 Fiddler Classic（免费版）或 Fiddler Everywhere（新版跨平台，部分功能收费）。日常测试用 Fiddler Classic 即可
  2. 双击安装包，一路 Next 完成安装，启动 Fiddler
  3. 首次启动会提示安装根证书，先不用管，模块 2 会正式配置

区域位置作用
菜单栏顶部File/Edit/View/Tools/Help 等菜单
工具栏菜单下方常用按钮：清空(Ctrl+X)、捕获(F12)、过滤、查找(Ctrl+F)
会话列表左侧大面板按时间列出所有抓到的请求（最重要）
详情面板右侧选中某请求后，查看 Headers/Body/Cookies/响应等

快捷键功能使用场景

3模块 2 HTTPS 解密（核心难点）

这是新手最容易卡住的一步。Fiddler 抓 HTTPS 的原理是「中间人代理」：用它自签的根证书对请求解密。要成功必须满足两个条件：① 流量经过 Fiddler；② 电脑信任 Fiddler 根证书。

2.1 开启 HTTPS 解密

  1. 菜单 Tools → Options → HTTPS 标签页
  2. 勾选 Decrypt HTTPS traffic（新版）或 Capture HTTPS CONNECTs（旧版）
  3. 弹窗提示安装证书，点击 Yes 自动安装到「受信任的根证书颁发机构」

勾选后，Fiddler 会开始解密经过它的 HTTPS 流量。

2.2 手动安装根证书（自动安装失败时）

若自动安装失败，或做移动端抓包需要证书文件：

  1. 菜单 Tools → Options → HTTPS → 点击 Actions → Export Root Certificate To Desktop，导出证书到桌面（.cer 文件）
  2. 双击证书 → 安装证书 → 选择「本地计算机」→ 放入「受信任的根证书颁发机构」→ 完成
  3. 重启浏览器，访问 https 站点验证是否解密成功（Fiddler 里能看到明文即成功）

2.3 浏览器证书校验失败的处理

部分浏览器（如 Chrome）有证书固定（Certificate Pinning），装了 Fiddler 证书仍可能报 NET::ERR_CERT_AUTHORITY_INVALID。测试环境常见解决办法：

  • 换用对代理友好的浏览器测试（如 Firefox 可导入证书）
  • 命令行启动 Chrome 忽略证书错误（仅测试用）：
代码
chrome.exe --ignore-certificate-errors --proxy-server=&quot;127.0.0.1:8888&quot;
【移动端关键】手机要抓 HTTPS，必须让手机也信任这个根证书。安卓 7.0+ 系统证书默认不被 App 信任（需装系统证书），iOS 需在「证书信任设置」手动开启完全信任。详见模块 6。

✎ 实操练习 开启 HTTPS 解密，访问 https://www.baidu.com，在 Fiddler 左侧找到该请求，右侧点开查看是否能显示明文 URL 和响应内容（而非 CONNECT 隧道）。

4模块 3 抓包与过滤

3.1 看懂一条请求

选中会话列表里某条请求，右侧详情面板有几个关键标签：

标签看什么测试关注点
Inspectors → Headers请求/响应头Content-Type、状态码、Cookie、鉴权头
Inspectors → Body请求/响应体接口参数、返回的 JSON 数据
Inspectors → CookiesCookie 详情登录态、Session
Inspectors → Timing各阶段耗时DNS/TCP/SSL/等待，定位慢在哪
Inspectors → Raw原始报文完整未解析内容

3.2 用过滤器缩小范围

抓包时请求很多，直接看会眼花。Fiddler 底部 Filter 栏可快速过滤：

  • 点击底部 Filter 按钮，勾选 Hosts → Show only the following Hosts，填入目标域名
  • 或用顶部搜索框 Ctrl+F 按关键字查找

更精细的过滤可用 FiddlerScript（见模块 5），示例：

代码
// 只显示包含 "api" 的请求（CustomFilters 里设置）
static function OnBeforeRequest(oSession: Session) {
    if (m_ScriptFilterHost != &quot;api.example.com&quot;) return;
    // 只保留目标 host
}

3.3 区分请求成功与否

会话列表里每行左侧有图标，快速判断：

图标含义
绿色正常完成（2xx/3xx）
红色感叹号请求失败/错误（4xx/5xx 或网络错误）
灰色被中断或被过滤
锁HTTPS 已解密

✎ 实操练习 打开一个你熟悉的网页或 App 后台，抓包后在会话列表里找出一个接口请求，说出它的请求方法、URL、状态码和响应体前几个字段。

5模块 4 断点与重放（测试最常用）

断点（Breakpoints）和重放（AutoResponder / Repeat）是测试工程师用得最多的功能，用于「改包测试」和「边界值测试」。

4.1 断点拦截请求（改请求）

  1. 在会话列表里右键目标请求 → Breakpoints → Before Requests（拦截请求发出前）
  2. 再次触发该请求，Fiddler 会拦截并弹出编辑框
  3. 修改请求参数/Header/Body → 点 Run 放行
  4. 观察 App/页面如何响应你篡改后的数据

典型用途：修改金额、数量、用户 ID 做越权/边界测试；去掉必填参数看后端校验。

4.2 断点拦截响应（改返回）

  1. 右键目标请求 → Breakpoints → After Responses（拦截响应返回前）
  2. 触发请求后，修改响应体（如把 code=0 改成 code=500）→ Run 放行
  3. 观察客户端对异常返回的处理（是否崩溃、是否有友好提示）

4.3 重放请求（AutoResponder）

AutoResponder 可把某个请求的响应替换成你预设的内容，用于 Mock 或重复测试：

  1. 打开右侧 AutoResponder 标签 → 勾选 Enable rules → 点 + 添加规则
  2. Match 填匹配 URL（支持通配符），Response 选择返回内容（可编辑 JSON）
  3. 再次请求该接口，Fiddler 直接返回你设定的内容，不再走真实服务器
【重放小技巧】右键某请求 → Repeat（Ctrl+R）可原样重发；Repeat Unchanged 重复发送；Saved Requests 可保存一组请求做批量重放。

✎ 实操练习 找一个登录接口，用断点把请求里的密码改成错误值，观察返回；再用 AutoResponder 把登录成功接口的返回改成「账号被封」，看 App 前端如何显示。

6模块 5 FiddlerScript 规则入门

FiddlerScript 是 Fiddler 的脚本扩展（基于 JScript.NET），能做自动改写、加头、Mock、日志记录等。菜单 Rules → Customize Rules 打开编辑器（CustomRules.js）。

5.1 两个核心钩子函数

代码
// 请求发出前触发（改请求）
static function OnBeforeRequest(oSession: Session) {
    // 在这里修改请求
}

// 响应返回前触发（改响应）
static function OnBeforeResponse(oSession: Session) {
    // 在这里修改响应
}

5.2 实用规则示例

示例1：给所有请求加一个自定义头（如测试环境标识）：

JSON / 配置
static function OnBeforeRequest(oSession: Session) {
    oSession[&quot;RequestHeaders&quot;][&quot;X-Test-Env&quot;] = &quot;qa&quot;;
}

示例2：把某接口的响应统一改成固定 JSON（Mock）：

JSON / 配置
static function OnBeforeResponse(oSession: Session) {
    if (oSession.uriContains(&quot;api.example.com/user&quot;)) {
        oSession.SetResponse(200,
            &quot;{\&quot;code\&quot;:0,\&quot;name\&quot;:\&quot;mock用户\&quot;}&quot;,
            &quot;application/json&quot;);
    }
}

示例3：记录所有请求到本地文件（便于复盘）：

JSON / 配置
static function OnBeforeRequest(oSession: Session) {
    FiddlerApplication.Log.WriteString(
        oSession.method + &quot; &quot; + oSession.fullUrl + &quot;\n&quot;);
}

5.3 保存与生效

  1. 编辑完 CustomRules.js → 菜单 File → Save（或 Ctrl+S）
  2. 脚本保存后自动编译生效，无需重启 Fiddler
【排错】脚本写错会导致规则不生效且无明显提示。保存后触发一次请求，若 Fiddler 右下角无报错即正常；也可在 Fiddler 里菜单 View → General 查看日志。

✎ 实操练习 在 CustomRules.js 里写一条规则：给所有发往 api.example.com 的请求自动加上 X-Debug: 1 请求头，保存后抓包验证该头是否出现。

7模块 6 移动端抓包（安卓 / iOS）

让手机流量经过电脑上的 Fiddler。核心两步：① 手机配代理指向电脑；② 手机信任 Fiddler 证书。

6.1 让手机流量经过 Fiddler

  1. 确认 Fiddler 监听端口：Tools → Options → Connections，默认 8888，勾选 Allow remote computers to connect
  2. 查电脑局域网 IP（cmd 里 ipconfig，找 IPv4 地址，如 192.168.1.100）
  3. 手机与电脑连同一 WiFi（或电脑开热点给手机连）
  4. 手机 WiFi 设置 → 配置代理 → 手动 → 服务器填电脑 IP，端口填 8888

6.2 安卓抓包

  1. 手机浏览器访问 Fiddler 证书地址：http://192.168.1.100:8888/FiddlerRootCert，下载并安装证书
  2. 安装后到 设置 → 安全 → 从存储设备安装，确认证书已装
  3. 打开 App 操作，Fiddler 即可看到请求
【安卓 7.0+ 难点】系统默认不信任用户安装的证书，HTTPS 抓不到。解决：用可 root 的模拟器把证书装为系统证书；或用低版本（6.x）模拟器；或让开发提供 debug 测试包关闭证书校验。

6.3 iOS 抓包

  1. iPhone 与电脑连同一 WiFi，按 6.1 配置代理
  2. Safari 访问 http://192.168.1.100:8888/FiddlerRootCert 下载描述文件并安装
  3. 关键最后一步：设置 → 通用 → 关于本机 → 证书信任设置 → 打开 Fiddler 证书的「完全信任」开关
  4. 打开 App 操作，Fiddler 即可看到 HTTPS 明文
【iOS 最易漏】只安装证书不够，必须去「证书信任设置」手动开启完全信任，否则 HTTPS 依然抓不到。

✎ 实操练习 用自己的手机（或模拟器）连上 Fiddler 代理，打开一个 App 完成一次操作，在 Fiddler 里找到该 App 发出的接口请求并查看明文内容。

8实战：定位一个「页面数据不对」问题

场景：App 里某列表页显示的数据和预期不符。用 Fiddler 定位是前端还是后端问题。

  1. Fiddler 里 Ctrl+X 清空 → 按 F12 开始捕获
  2. App 里刷新该列表页，触发请求
  3. 在 Fiddler 找到列表接口（用 Host 过滤或 Ctrl+F 搜关键字）
  4. 查看响应体 Body：
  • 若返回的数据本身就错 → 后端问题，提单给后端，附抓包截图
  • 若返回数据正确，但页面显示错 → 前端解析/渲染问题，提单给客户端
  1. 用断点改响应做验证：把返回数据改成已知正确值，看页面是否跟着变，进一步确认

这就是「抓包定位责任方」最典型的用法——一眼看清数据在哪个环节出错。
